# HeartFailurePath handoff, 2026-11-12

A cold-start document for whoever takes this project next (a person or a coding agent). It says what the tool is, where the work stands, how to run and check it, what was done and why, and what is still open. Detail lives in the documents this one points to.

## 1. State in one paragraph

HeartFailurePath is a client-side, deterministic decision-support tool for outpatient heart failure drug therapy (Vite, React 19, TypeScript; no server, no AI calls). All recent work is on branch `refactor/glucosepath-alignment`, open as pull request #1 on `beilerman/HeartFailurePath`. The branch is 115 commits ahead of `main` and **has not been merged**. `main` deploys to production on Vercel automatically, so merging is a release and is the physician owner's decision. The full gate passes on the branch head, and CI and the Vercel preview pass on the pull request.

## 2. Run and check

Node 22 or later.

```bash
npm install
npm run dev            # Vite dev server
npm run gate           # everything below except build; run before every commit
npm run build
```

| Command | What it checks |
|---|---|
| `npm run typecheck` | TypeScript |
| `npm run golden` | Engine output for 344 sample patients x 3 insurance tiers (1,032 runs) is byte-identical to the snapshot |
| `npm run verify` | 371 checks: per-scenario clinical assertions plus structural invariants |
| `npm run audit:hundred`, `audit:mistakes`, `audit:red` | Three older invariant batteries |
| `npm run audit:pricing` | Every drug has a price under every plan, never above cash |
| `npm run fuzz` | 5,000 seeded random patients against safety and consistency rules written independently of the engine |

Changing engine output on purpose: run `npm run ranking:diff` first (it reports how many top picks, alerts and warnings changed against the snapshot), read the differences, then `npm run golden:update`, and bump `RULESET_VERSION` in `services/rulesetVersion.ts`. Never update the snapshot to make a failure go away.

Larger sweeps on other seeds: `npx tsx scripts/fuzzSweep.ts 15000 <seed>`. Set `FUZZ_EXAMPLES=12` to print more examples per finding.

## 3. Where things are

```
App.tsx, components/            UI: form (components/patient-form), results, score ledger, formulary and evidence tabs
services/simulationService.ts   The facade: one entry point, generateAndScoreModifications(patient, availableNames, prices)
services/engine/                The pipeline, one stage per file:
  gates.ts            input audit, alerts, hard stops (SBP below 90, potassium 6.5 or higher)
  eligibility.ts      numbered rules E01-E20, each with a plain reason
  candidates.ts       builds candidate changes: add, titrate, swap, remove; forced edits
  effects.ts          projects blood pressure, heart rate, potassium, weight, NT-proBNP; warnings
  scoring.ts, scoreModel.ts, domains.ts   eight weighted domains plus named adjustments, with a ledger
  selection.ts        display floors, ranking, up to three distinct options
  explain.ts          monitoring, follow-up, labels, alert reconciliation
  intolerance.ts, allergy.ts, contraindications.ts, thresholds.ts, regimenUtils.ts, renalChange.ts
services/clinicalPredicates.ts  shared clinical predicates (also used by the form)
services/pricingService.ts      price table and plans
constants.ts                    the formulary: 32 drugs, doses, effects, facts, contraindication checks
data/scenarios.ts               344 sample patients (also the form's sample menu)
scripts/                        the checks listed above
```

Rules that keep the code honest (each enforced by `verify`): engine code holds no drug-name literals (drug knowledge lives in `constants.ts` as facts); every selectable form option is read by the engine; a drug's contraindication list is its single source; sample patients are fixed points of the form's own eGFR and BMI derivation; side-effect rates are display-only.

## 5. What was done on this branch

**2026-11-10: architecture and drug data.**
- The 3,400-line engine was split into the staged pipeline above, mirroring the GlucosePATH design: numbered eligibility rules with reasons, an eight-domain weighted score with a visible ledger, patient-priority weight profiles. A golden snapshot guarded each step.
- All 32 drugs were checked against labels, trials and guidelines; corrections were applied only after verification against a primary source.
- The UI was reworked: answer-first results, an evidence tab, copy-to-chart.

**2026-11-11: clinical decisions and guideline alignment.**
- Three owner decisions implemented: outpatient scope; potassium and kidney function required before a RAAS inhibitor or MRA is started or increased (rule E16); a Balanced / Prioritize-foundational ranking choice; over-budget options labelled "for discussion only".
- Aligned with the 2026 ESC heart failure guideline (read in a browser; notes in the medication review folder) and the 2022 AHA/ACC/HFSA text: potassium and creatinine rules, phenotype definitions, dose table, pregnancy, device / advanced HF / AF alerts.
- Added a baseline-creatinine input, a double-the-daily-dose cap per visit, graded dose credit, and a congestion display rule.

**2026-11-12: three adversarial review passes.**
- Pass 1: a seeded random-patient sweep and four reviewers found 17 systemic defects (dose-cap bypass for combination strengths, duplicate drugs in one option, exact-name-only allergy matching, NaN inputs, order dependence, validation bypass, others). All fixed.
- Pass 2: the 17 items first left open were fixed, each with an enforcing test (fixtures matching the form, potassium projection, scoring quirks, intolerance table, unread form options, pricing cap, one target dose per drug, one potassium ladder, label-versus-guideline differences as data, chart-note header, self-reversal).
- Pass 3: four new reviewers and a visit-by-visit probe. Fixes are in commit `fa34d68`; 17 reproduced items remain open.

## 6. Open work

**Decisions for the physician owner** (the tool currently does what is stated):
- Losartan target is 150 mg (2026 ESC, HEAAL); the US guideline gives 50 to 150 mg.
- RAAS inhibitor increases are held above potassium 5.2, the same as new starts.
- A potassium binder is not reduced while potassium is 5.0 or higher.
- Rule E20: no RAAS inhibitor start, increase or switch at a measured eGFR below 20.
- The age-over-80 dose limit was removed (it had no source).
- A current MRA is removed below eGFR 30 (spironolactone) or 25 (finerenone); the ESC supplement would halve at below 30 and stop below 20. Not changed; needs a decision.
- The Entresto Medicare copay in the table (74) is above cash (60); the patient is shown 60.
- Earlier questions in `docs/clinical-decisions-2026-11-11.md` ("Clarifications still needed") and `docs/medication-review-2026-11-10/README.md` ("Open for physician review").

**Defects reproduced and not yet fixed:** the 17 items under "Reproduced, NOT fixed" in `docs/adversarial-review-2026-11-12.md`. The first four matter most: RAAS dose changes do not move projected potassium (which also causes binders to be attached to dose reductions); the MRA kidney thresholds; completeness credit ignoring renal caps; dose-reduction steps and their wording.

**Tests to write:** scenarios for the third-pass fixes that are covered only by the random sweep or a one-off reproduction (pregnancy switch dose, ARB and angioedema allergy handling, the new warnings and alerts, alert reconciliation, the negative-creatinine form case).

## 7. Working conventions

- Clinical numbers change only with a source. State in the code comment whether a number is a label, a guideline or engine policy, and add the row to `docs/evidence-matrix.md`. Paraphrase sources; do not copy label or guideline text.
- Fix the class of problem, then add the check that would have caught it (`scripts/optionInvariants.ts` and `scripts/optionScenarioChecks.ts` take new checks; `scripts/verifyScenarios.ts` is near TypeScript's control-flow size limit).
- Patient collections are `Set`s: clone with `clonePatient`, never JSON.
- Commit messages state the clinical change and the reason. Keep `memory.md` current when a decision is made.
- The 2026 ESC and 2022 US guideline pages open in a browser; automated fetches of those sites are blocked. DailyMed is reachable for label checks.
