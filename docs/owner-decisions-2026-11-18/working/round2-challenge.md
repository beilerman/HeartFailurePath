Read-only on the engine. All experiments ran on a COPY (`.../scratchpad/round2/repo/`, env switches `HF_NOBONUS`, `HF_NOBANDS`, `HF_SWAP2`; scripts `scripts/r2sweep.ts`, `r2one.ts`, `r2dose.ts`). ## A. Headline findings (things that change draft-2)

1. **Item 11 is refuted outside the reference runs.** With the +15 set to 0, the first option changes in 15 of 6,000 random patients (displayed set 15, displayed order 28), while 0 of 1,032 reference runs change. The bonus is NOT uniform across options when one option is a like-for-like SWAP of the contraindicated drug and another is "remove it and add something else". Example (seed 750): HFpEF (LVEF 55), eGFR 43, K 5.1, on finerenone (contraindicated here), dapagliflozin, vericiguat. Option 1 "swap finerenone to spironolactone 12.5" carries the bonus (+8.6 after the divisor), scores 71; the remove-and-add-sacubitril/valsartan option scores 63; lisinopril option 60. At bonus 0 the order becomes 63, 62, 60 and the first option is sacubitril/valsartan (a RAAS inhibitor, Class IIb at preserved EF) instead of an MRA (Class I). The bonus is therefore a hidden "stay in class" preference worth 8.6 ranking points. Draft-2's "it never ranks one above another" is false. The divisor is fixed per patient (indicated foundational slots, `scoring.ts:378`), so the bonus is uniform ONLY across options that all contain a swap.
2. **Item 10's premise "the four band penalties cannot change the order" is false outside the reference runs.** Zeroing them changes the first option in 39 of 6,000 random patients and the displayed set in 91 (0 of 1,032 reference runs). I confirmed that in the case I traced (seed 224) both displayed options carried the same -46 (HR 49 -40, SBP 91 -6) and the same warning penalty, so the penalty is identical across options; the change arises downstream (one option disappears from the displayed set when the penalty is removed). I did not trace the exact selection rule; it is an unexplained interaction that the owner must not be told does not exist. Also note `selection.ts:88-93` (`SEVERE_PROJECTED_SAFETY`, `isProjectedSafetyClean`) reads these adjustment CODES from every option's ledger for the "foundational_first" ranking mode; deleting the adjustments removes input to that comparator (today inert because `risk_screen` is observed-state-only, so "harmful" is never true, but it is a coupling the draft does not mention).
3. **Item 6 "defect, no owner decision" is wrong.** I implemented "switch plus up to two additions over all missing pillars" (the generator today uses only `pillarLists[0]` and one addition, `candidates.ts:927-945`, confirmed). Result: the first option changes in 46 of 1,032 reference runs (LVEF 41-49: 5 of 57; LVEF <=40: 41 of 864; >=50: 0), displayed set changes in 49. Mean guideline concordance of the lead goes 73.01 to 73.44; targets 3 of 7 unchanged. The previous round counted 18 of 20 runs "where it would be allowed"; the real footprint is 2.5 times that. Typical change: the lead gains a fifth drug (for example "Carvedilol + Eplerenone + Furosemide + sacubitril/valsartan" becomes the same plus dapagliflozin; "lisinopril" becomes "sacubitril/valsartan" in acute-decompensation scenarios). A single-addition-from-any-pillar variant changes nothing beyond that. This is a policy-visible change (more drugs in the lead in acute states). Owner sees examples first.
4. **Item 15 contradicts item 1.** Item 15 says the ITT-versus-on-treatment pairing's understatement "applies to every drug alike". It does not: a START is valued at the ITT relative risk (which correctly embeds the 32.5% who stop), whereas a drug the patient is KEEPING has already survived the early-stopping period, so its ITT value understates it by up to 1.48x (0.80 to 0.72). The understatement therefore applies to kept drugs and not to starts, biasing the engine toward start/switch over keep (the unsafe direction for stop decisions). Draft-2 states the 1.48 correctly but draws the wrong conclusion from it.
5. **Item 14e's 8.1% is not an excess.** PMID 36722321 abstract: 41 studies, 7,931 FCM-treated patients, HF subgroup 14%; "post-baseline moderate or severe hypophosphataemia (<2.0 mg/dL)": HF 8.1% (versus 12.8% non-dialysis CKD, 30.1% women's health, 51.0% GI); <1.0 mg/dL in one HF patient (<0.1%). It is an incidence in FCM-treated HF patients pooled across studies with no placebo-arm rate in the abstract, and the engine's 66.35 is a placebo-subtracted excess (PHOSPHARE-IDA 74% versus 8%). Replacing an excess by a gross incidence mixes definitions in the table (a table whose rule is drug minus control). The placebo rate in the HF trials is probably 0 to a few percent (not read), so the true excess is probably 5 to 8, close to the 8.1 but undetermined. Direction right, number not verified as an excess, window unstated (the analysis pools short and long trials).
6. **Item 5's description of the regression alternative is wrong.** Draft-2 says the regression prior moves the neutral ACE-inhibitor preserved-EF death row "from 1.04 to 0.98 or 0.90". Statistics review table: regression gives 0.980; 0.898 is the pooled-mean-centred variant. The author attributed another variant's failure to the method he rejected.

## B. The OVERRULED items

**Item 1 (concave curve from observational data) - author right on the number, wrong that the floor is neutral.** Observational BIOSTAT-CHF dose comparisons are confounded (patients not reaching dose had HR about 1.7). Declining to adopt a number is right. But item 9's floor imports the concavity anyway (see item 9). Item 1 as revised (start credit 1, increase credit at the dose reached, cap at highest allowed dose) matches the statistics reviewer's rule (c); I measured 3 of 1,032 first options for (c) and 9 for the cap (sensitivity table), so ACCEPT. Residual objection: same drug, same patient: if started today it earns 1.0; if it was started yesterday it earns 0.364, so the "no change" arm of next visit is worth far less than the "start" arm of this one. Not a bug within a visit, but a visit-to-visit discontinuity the owner should be told about.

**Item 2 (utilities exist and need sourcing) - the author is partly right, the principles reviewer partly right, and the direction survives where the numbers do not.** What I could find (PubMed):
- Hospitalization / health state: Goehler 2009 (PMID 18647251; EPHESUS EQ-5D): utility 0.88, 0.85, 0.84, 0.82 for 0, 1, 2, 3+ cardiovascular rehospitalizations; NYHA I-IV 0.90, 0.83, 0.74, 0.60. Hawkins/SHIFT model (PMID 28205056): HRQoL falls 0.07 (NYHA I) to 0.21 (NYHA IV) within 30 days of a hospitalization; ivabradine +0.01.
- KCCQ to utility: two mappings exist (PMID 33724402, two US HFrEF cohorts, R2 0.48-0.58; PMID 33344768, PARADIGM-HF, R2 0.45-0.52, mean absolute error 0.10-0.11). The abstracts do not give the slope; I could not confirm the statistics reviewer's 0.004 QALY per point per year.
- Death / life expectancy: nothing retrievable in two searches (it would come from life tables or MAGGIC-type survival, not from a utility paper).
- Adverse events by severity: nothing found for HF.
So sourced values exist for hospitalization and KCCQ, not for death or for adverse events. The decisive calculation: with hospitalization rate about 1.5 times the death rate (the statistics reviewer's assumption; PARADIGM-style control arms have them about equal) the current 0.22:0.30 weighting needs a QALY loss per admission of 0.489 times the QALY loss per death, about 3.4 QALY at 7 QALY per death. Sourced direct losses are 0.01 (30 days at -0.14) to about 0.15 (persistent 0.03 per year over a few years). Counting post-admission mortality as well would double count it with the death outcome. So the hospitalization over-weighting (5x or more) is robust to the sourced range, the death "twofold" under-weighting is not (it depends on life expectancy and on constant hazard), and the side-effect and symptom ratios cannot be sourced at all. Draft-2 says "direction is robust" for all three; only hospitalization is.
Strongest case that a pure quality-of-life scale is the WRONG frame: (a) it prices death by remaining life expectancy, so the tool silently ranks an 85-year-old's mortality benefit below a 55-year-old's and a frail patient's below a robust one, which is the disability/age bias of QALYs and cannot be explained away by "population average" because the tool shows patient-level options; (b) HF patients and clinicians often value avoiding admission and keeping independence above life-years (patients have been shown to trade survival time for symptom relief; not searched, from memory), so a population utility imposes one trade-off that the tool cannot let the patient move; (c) with death near 0.6 the ranking becomes a mortality ranking and every drug whose benefit is admissions or symptoms (SGLT2 inhibitor at preserved EF, IV iron, GLP-1, ivabradine, digoxin) is demoted, which is exactly the clinically important opposite of the trial primary endpoints and of how clinicians treat HFpEF; (d) utilities derived from trial EQ-5D are collected away from events, undercount admission effects (the SHIFT paper says so) and have ceiling effects; (e) one common scale is attractive for merging engines (P5), but the HTN engine has no sourced utilities either (principles review). What a clinician would lose: the ability to see and move the trade-off between "live longer", "stay out of hospital" and "feel better". Recommendation: keep outcomes as separate displayed rows in absolute terms (item 16) and let a utility scale be an optional, labelled summary, not the ranking engine.
Verdict on the overrule: ACCEPT the method direction only as a research task; keep the present numbers labelled policy (agreement with the principles reviewer on what to ship). The claim that "53 to 62 of 337 first options would change" is a result of the author's own unsourced utilities and should not be quoted to the owner as the effect of "sourced" weights.

**Item 5 (regression prior rejected) - author's conclusion defensible, one reason wrong.** See A6. Additional objection: the author's own choice (per-outcome null prior, 0.030/0.094) is also a fitted number (k about 19 each, second moments around zero that include the mean effect: the statistics review shows 70 percent of the pooled tau2 is mean effect). It is no less "hand-set" than a regression. The null centre is defended as explainable ("less certain means closer to no effect"), which is a legitimate P4 argument but also builds in a conservative bias the draft separately lists as an open decision (N-3).

**Item 10 (multiplier by baseline SBP) - author right that a usable absolute number exists; wrong about how to apply it and about the reviewer.** From the source (Bohm 2017, PMC6251522 Table 4, verified): symptomatic hypotension, enalapril versus sacubitril/valsartan: SBP <110 125 (13.7%) vs 213 (25.5%); 110-<120 101 (10.7%) vs 143 (14.4%); 120-<130 87 (8.5%) vs 119 (11.4%); 130-<140 50 (6.7%) vs 66 (9.0%); >=140 25 (4.2%) vs 47 (8.0%). Differences in points over a median 27 months: 11.8, 3.7, 2.9, 2.3, 3.8. The last column of that table gives the interaction p for symptomatic hypotension as 0.21 (not significant), which supports the clinical reviewer's statement that the RELATIVE risk is about constant; the author's point that an absolute difference nonetheless varies is also true, and a banded absolute difference is the right quantity if one wants a multiplier. The engine row, however (`ARNI-R5-hypotension`, 4.806 per year, `harmEvidence.json`) is the SUM of two parts: SOLVD enalapril-versus-placebo excess 2.506 plus the PARADIGM sacubitril/valsartan-minus-enalapril difference 2.300. Only the second part is resolved by SBP. A ratio applied to the whole row would multiply the SOLVD part too. Correct multipliers on the PARADIGM part relative to its all-patient difference of 4.83 points: <110 2.44; 110-120 0.77; 120-130 0.60; 130-140 0.48; >=140 0.79 (not monotone; the >=140 band rests on 25 and 47 events). So the multiplier is a low-SBP spike (SBP <110) with a mild reduction above, not a one-sided multiplier. The existing multiplier `M-age75-hypotension-ARNI` would multiply with it (the code multiplies all applicable multipliers, `harmBurden.ts`), and age and low SBP are correlated. PARADIGM was run-in selected (patients had to tolerate both drugs), so the low-SBP excess in the open population is probably larger. Net: ACCEPT building a banded modifier for the ARNI-minus-ACEi component only, after the owner sees the effect; do NOT describe it as a replacement for the safety penalties. DAPA-HF (volume depletion 12.3 vs 13.3, 6.1 vs 7.8, 4.4 vs 4.7, 4.7 vs 4.9 by SBP, per the clinical review's page extraction; I did not re-read it) supports "no modifier for SGLT2 inhibitors".
Code facts requested: the burden is an ABSOLUTE excess (drug rate minus control rate on a one-year scale; `harmBurden.ts` header and `HarmRow.one_year_excess_pct`). For this row the control is the active comparator (control_type "active", enalapril) composed with the SOLVD placebo comparison. The four band penalties (`scoring.ts:407-427`) key on recorded SBP, HR, K (the observed patient; `risk_screen.basis = 'observed_state_only'`), are identical across the options of one run (confirmed in the case I traced), and 0 of 1,032 reference runs and 0 of 337 scenario leads change when they are zeroed; but see A2. The per-option "DANGEROUS_WARNINGS" penalty (-8 each) charges (i) every penalized warning the option itself raises (`sim.warnings` filtered by `isPenalizedWarning`, minus a marker list: titration, routine monitoring, "Binder Required" is deliberately counted) and (ii) every warning already true of the current regimen, counted for every option (`baselineDangerWarnings`) so that none wins by merely cutting a drug. It does discriminate between options for new hazards the option adds (hyperkalemia, ARNI start at SBP <100, washout, digoxin K bands, Furoscix), and it does not discriminate for pre-existing ones.

**Item 12 (shrunk interaction, about 0.91) - arithmetic correct, concept contestable, and internally inconsistent with the hospitalization decision.** Checks: SE sinus = (ln 0.80 - ln 0.67)/3.92 = 0.0453; SE AF = (ln 1.14 - ln 0.83)/3.92 = 0.0809; interaction ln(0.97/0.73) = 0.284, SE 0.0927; weight B = 0.030/(0.030+0.0086) = 0.777; shrunk 0.221; AF value = exp(ln 0.73 + 0.221) = 0.91. Correct. Objections: (i) the prior used (0.030) is the second moment of the effect of DRUG-OUTCOME ROWS around zero (SD 0.17), i.e. it allows a rhythm subgroup of the same drug to differ by a ratio of 0.7 to 1.4 at 95 percent. That is a fitted number being reused for a different quantity (an interaction within one drug). "Adds no new number" is true of the file but not of the reasoning. With the statistics reviewer's 0.05-0.10 the value is 0.79-0.85. Any answer from 0.79 to 0.97 is defensible; 0.91 is within it. (ii) The base is Kotecha's sinus 0.73, but the engine's own reduced-EF beta-blocker death row is 0.66 (about 0.69 after shrinkage). Applying the same shrunk interaction to the engine's base gives about 0.66 x e^0.221 = 0.82, not 0.91, so the AF row and the non-AF row come from different pools. Pick one base. (iii) Later evidence: I found no RCT after Kotecha 2014. The same Beta-Blockers in Heart Failure Collaborative Group published (Kotecha 2017 JACC, PMID 28467883; 11 trials): sinus rhythm 0.73 (0.67-0.79), AF 0.96 (0.81-1.12), interaction by heart rate p 0.48 within AF; it is a re-analysis of nearly the same data, not independent confirmation. The rate-control reason for a beta-blocker in AF remains outside the outcome scale. (iv) Hospitalization: draft-2 leaves the AF patient with the full beta-blocker admission benefit (0.64 or its shrunk value) while death goes to about 0.91. The only rhythm-specific admission data are Cleland's CARDIOVASCULAR hospitalization hazard ratios in AF (0.97, 0.75, 1.01, 0.90 by EF band; 1.15 at 40-49), which show no consistent benefit. Keeping 0.64 in AF credits the beta-blocker in AF primarily through the outcome the evidence does not support. ## D. Item 9 floor ("credit never less than dose divided by the trial dose, because dose-response is concave")

Concavity is measured for two drugs in one class: lisinopril (ATLAS) and losartan (HEAAL). Of the four implied credits, ATLAS death 0.626 at 27 percent of the anchor is concave, but ATLAS HF admission 0.317 at 27 percent is about linear, and the data file's own c0 values range 0.206 to 0.565. A line through the origin is the weakest form of the concavity claim, and it is what the floor uses. I computed, with the engine's own functions, every labelled dose where dose/anchor exceeds the current curve:
- sacubitril/valsartan 24/26 bid: 0.182 to 0.267; 49/51 bid: 0.364 to 0.533 (anchor 375 mg total daily; no placebo or low-dose randomization exists, the row is a putative-placebo analysis anchored on SOLVD)
- spironolactone 12.5: 0.182 to 0.481; 25: 0.364 to 0.962 (the anchor-equals-start artefact the floor is meant to cure)
- eplerenone 25: 0.364 to 0.595 (anchor 42 mg)
- finerenone 10: 0.182 to 0.366; 20: 0.364 to 0.733 (anchor 27.29 is borrowed from steroidal MRAs and is in a different drug's milligrams; a floor on that ratio is meaningless)
- ivabradine 2.5 bid: 0.182 to 0.385; 5 bid: 0.364 to 0.769
- digoxin 62.5 mcg: 0.364 to 0.5
So the floor can over-credit (a) drugs whose benefit is driven by a threshold or an achieved physiological target rather than milligrams (ivabradine: heart-rate reduction; digoxin: serum concentration; vericiguat, where the 2.5 mg start is a run-in step and benefit relates to reaching 10 mg), (b) any class where the anchor is a cross-drug proxy (finerenone), and (c) the ARNI where the dose-response is not randomized at all. It also lifts the credit for dose REDUCTIONS and forced reductions (they are valued by the same curve), making reductions look cheaper in the same direction. It is not the defect fix described ("spironolactone 25 earns 0.364"); that artefact needs the anchor to be the trial dose with the curve anchored on the label start only when start < anchor by a margin. ACCEPT only for the drug rows where the anchor and the dose are in the same drug's units and a dose comparison or a pharmacodynamic argument exists (spironolactone, eplerenone, ACE inhibitors, ARBs, beta-blockers), and apply it as a labelled assumption; EXCLUDE sacubitril/valsartan, finerenone, ivabradine, digoxin, vericiguat. Needs the owner to see sacubitril/valsartan 49/51 move 0.364 to 0.533: it is a 46 percent increase in the credit of the commonest first option.

## J. Order of work before the clinician case review on a frozen rule set
