# HeartFailurePath Evidence Matrix

Describes rule set 2026-11-22.4, the version stamped on printed notes. Each row was checked against the program code and the evidence tables for that rule set.
Scope: every row says what the tool does, why, and what the rule rests on. The Evidence column opens with the basis: a drug label (which section), a trial or pooled analysis (which), a guideline (used by this tool for safety and eligibility rules only, never to rank options), or a choice made in building the tool. The tool's own name for that last basis is engine policy; it means a design decision, not a finding from a trial, label or guideline. Ranking uses measured trial effects, measured harm rates, price and dosing burden. Guideline recommendations are shown for reference and are checked against the result, not used as inputs. This table is a record of the rules, not an independent validation study.

## How options are scored

The model, its formulas and its weakest rows are described in the project's first-principles model report. Per-row evidence (hundreds of rows) is in the four evidence tables on this tab (outcomes, symptoms, side effects, dose credit) and is not copied here. The older statements that outcome domains carry no weight, and that no score is a quantified treatment benefit, no longer apply: death, hospitalization, symptoms and side effects now carry the ranking weight, and special-feature bonuses no longer rank options.

## Current regimen, exposure and what the tool does not predict

All 32 medications and 122 dose and frequency entries are covered. The tool records and screens on measured values; it does not forecast an individual's physiological response to a regimen change. Earlier descriptions of numerical medication response (projected blood pressure, potassium, heart rate, ejection fraction or BNP) no longer describe the tool.

## How to use this matrix

Each row has a stable rule identifier that other documents, tests and notes can refer to. The Rule column on the screen is that identifier.

Columns:
- **Rule ID**: stable identifier for the clinical behavior.
- **Implementation location**: the code or data file that carries the rule (not shown on the screen).
- **First-principles rationale**: physiology/pathophysiology basis.
- **Evidence anchor**: the basis (label, trial or pooled analysis, guideline, or a choice made in building the tool) and the source.
- **Evidence strength**: how directly evidence supports the implemented rule.
- **Calibration note**: which numbers come from a source and which are choices made in building the tool.
- **Clinical risk if wrong**: primary harm mode.

## What the checks do and do not show

The reference scenarios and checks confirm that the rules behave as written: safety floors, contraindications, duplicate removal, interaction warnings, Furoscix safety and expected outputs. Passing them is necessary but does not show clinical validity.

A new clinical rule, warning, score domain or threshold should be added to this table when it is added to the tool.
